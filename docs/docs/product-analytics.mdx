# Product Analytics

Moneat Product Analytics is an enterprise feature that provides privacy-focused, Plausible-style web analytics. It requires no cookies, stores no personal data, and runs entirely on your own infrastructure.

## Key Features

- **Cookie-free** — Sessions derived from server-side hashing (daily salt + domain + IP + UA), never from client storage
- **No personal data stored** — IP addresses and User-Agent strings are used transiently for enrichment, then discarded
- **Sub-1KB tracking script** — ~670 bytes gzipped, minimal performance impact
- **SPA support** — Automatic tracking of client-side navigations (History API)
- **Custom events** — Track conversions, signups, and any user interactions
- **Respects Do Not Track** — Honors the browser's DNT setting
- **Real-time visitors** — See active visitors using Redis HyperLogLog
- **Funnel analysis** — Measure conversion through ordered event sequences

## Setup

### 1. Get Your Project Key

Navigate to your project settings in Moneat. Your project's public key (sentry key) is used to authenticate analytics events — the same key used for error monitoring.

### 2. Add the Tracking Script

Add the following script tag to your website's `<head>`:

```html
<script
  defer
  data-domain="yoursite.com"
  data-key="your-project-public-key"
  src="https://your-moneat-instance.com/js/m.js"
></script>
```

| Attribute | Description |
|-----------|-------------|
| `data-domain` | Your website's domain (must match the project) |
| `data-key` | Your Moneat project's public key |
| `data-api` | *(Optional)* Override the API host if different from the script origin |
| `src` | URL to the tracking script served by your Moneat instance |

### 3. Or Use the NPM Package

For SPA frameworks (React, Vue, Next.js, etc.):

```bash
npm install @moneat/analytics
```

```typescript
import { init, trackEvent } from '@moneat/analytics'

init({
  domain: 'yoursite.com',
  apiHost: 'https://your-moneat-instance.com',
  key: 'your-project-public-key',
})

// Track custom events
trackEvent('Signup', { plan: 'pro' })
```

## Custom Events

Track any user interaction with custom events:

**Script tag:**
```javascript
// Global API exposed by the tracking script
moneat.track('Signup', { plan: 'pro' })
moneat.track('Download', { file: 'whitepaper.pdf' })
```

**NPM package:**
```typescript
import { trackEvent } from '@moneat/analytics'

trackEvent('Signup', { plan: 'pro' })
trackEvent('Download', { file: 'whitepaper.pdf' })
```

## Dashboard API

All analytics API endpoints are under `/v1/analytics/{projectId}/` and require JWT authentication.

### Endpoints

| Endpoint | Description |
|----------|-------------|
| `GET /overview` | KPI metrics: visitors, pageviews, bounce rate, avg duration |
| `GET /timeseries` | Time-bucketed visitor and pageview data for charts |
| `GET /pages` | Top pages by visitors |
| `GET /entry-pages` | Top entry pages |
| `GET /exit-pages` | Top exit pages |
| `GET /sources` | Top referrer sources |
| `GET /utm/{param}` | UTM breakdowns (source, medium, campaign, term, content) |
| `GET /locations` | Country/region breakdown |
| `GET /devices` | Browser, OS, device type breakdowns |
| `GET /events` | Custom event names and counts |
| `GET /realtime` | Active visitors in last 5 minutes |
| `GET /funnel` | Funnel analysis for ordered event sequences |

### Common Parameters

| Parameter | Values | Description |
|-----------|--------|-------------|
| `period` | `today`, `7d`, `30d`, `month`, `6mo`, `12mo`, `custom` | Date range |
| `date_from` | `YYYY-MM-DD` | Start date (required when `period=custom`) |
| `date_to` | `YYYY-MM-DD` | End date (required when `period=custom`) |
| `comparison` | `previous_period`, `year_over_year` | Comparison period |
| `filters[]` | `property:operator:value` | Filter results |
| `limit` | integer | Max results (default: 100) |

### Filter Operators

- `is` — Exact match
- `is_not` — Exclude match
- `contains` — Substring match
- `not_contains` — Exclude substring

**Example:** `/v1/analytics/1/pages?period=30d&filters[]=country_code:is:US&filters[]=browser:is:Chrome`

## Privacy Architecture

```
Client                    Server                              Storage
  |                         |                                    |
  |-- pageview event ------>|                                    |
  |                         |-- Extract IP (from headers) ------>|
  |                         |-- Parse User-Agent --------------->|
  |                         |-- GeoIP lookup (IP -> country) --->|
  |                         |-- Generate session hash:           |
  |                         |   SHA-256(salt|domain|IP|UA)       |
  |                         |                                    |
  |                         |-- DISCARD IP address               |
  |                         |-- DISCARD raw User-Agent           |
  |                         |                                    |
  |                         |-- Store enriched event ----------->| ClickHouse
  |                         |   (session_id, country, browser,   | (no PII)
  |                         |    pathname, referrer, etc.)        |
```

- **Daily salt rotation** ensures the same visitor gets a different session ID each day
- **No cross-site tracking** because the domain is part of the session hash
- **Salt stored in Redis** with 48-hour TTL (handles timezone edge cases)
- **HyperLogLog** for real-time visitor counts — probabilistic counting without storing identifiers

## Environment Variables

| Variable | Required | Description |
|----------|----------|-------------|
| `GEOIP_DB_PATH` | No | Path to MaxMind GeoLite2-City database (default: `/usr/share/GeoIP/GeoLite2-City.mmdb`) |

If the GeoIP database is not available, analytics will work normally but location data will be empty.
